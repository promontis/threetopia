NEW / COMPACT 3D MAP TILES

One tile. One representative component.

Threetopia provides the terrain and an empty slot, for both the playable world and its simplified 3D map. Creators select one recognizable component from their scene to represent it on the map. Lagoon uses one connected group: the four distinct native treehouses, Origin, Nest, Perch and Canopy, with their three original hangbridges. Their relative positions remain unchanged. A component can contain a connected group, but the entire group shares one slot and one budget. Deck surfaces come from every native board front face. Adjacent coplanar boards merge in pairs at tile detail and groups of up to six in overview, removing subpixel gaps and bevels without cutting holes in bridge spans. Fewer native leaf cards retain the original cutout texture, transforms and crown shape, with coverage compensation.

import {createDesertTile} from '@threetopia/world-map/desert-tile';
import {loadLandmark, addLandmarkWind} from '@threetopia/world-map/landmark';

const tile = createDesertTile();
const landmark = await loadLandmark(absoluteGLBURL, 'tile');
tile.mount(landmark.root, landmark.metrics);
scene.add(tile.root);

const time = {value: 0};
addLandmarkWind(landmark.root, time);
// Advance this shared clock in the host render loop.
// Dispose both owners when removing the tile:
// landmark.dispose(); tile.dispose();

The host owns the edges

The desert-v1 shell has a circular creator slot at 62.5% of its radius. The map tile has a radius of 12 units, a slot radius of 7.5 and a slot height of 16. Anchor your component at local ground level, Y=0, and leave 0.1 units of space for wind. The corresponding shell from createDesertTile({representation: 'world'}) has a radius of 400 metres and a slot radius of 250 metres. Its heightAt(x,z) supplies the terrain surface for later world integration.

Use axial coordinates and tileCentre(q,r,radius) for placement. Shared desert edges meet at the same height with zero slope. The creator never owns the outer landscape or a separate camera. The default slot is flat. Lagoon instead uses createDesertTile({surface, waveTextures, time}) with its sampled village-ground.json preset. The four islands, surrounding lagoon and nearby islets come from the original terrain, sampled at 2.4 source metres, with the same origin at sea level and uniform scale as all four treehouses and bridges. Tree positions and bridge endpoints are recorded in source and map coordinates in the component manifest. Only the outer 1.5 map units blend into the shared edge. A water preset does not make the whole slot a flat, dry floor. Load the two wave textures relative to the preset URL using linear colour space and repeat wrapping; the caller owns their disposal. Water uses the host clock, original wave textures and a simplified map shader. It adds one draw call and about 171 KiB of decoded textures, with no scene-reflection pass. Shared edges retain their original height. The preview's Aansluitingen button demonstrates six adjoining empty tiles; they are test slots, not published worlds.

Four compact worlds together

Open Lagoon, Tidewater, Sakura and Punk together ↗

The compact-v1 host profile reduces the radius from 12 to 9 map units (400 to 300 world metres), keeping the same creator slot and limits. Four adjoining creator slots have five shared edges, with no empty spacer tiles. The current map composes them in one continuous coastline, with shared sand, grass, rocks and water. Lagoon retains its connected village; Tidewater supplies its original lobster boat, dock and coastal plants; Sakura includes its native riverboat, arched bridge, pagoda and cherry trees; Punk floats on a host-owned platform with six boosters and a footbridge. Sakura compresses the source-world distances between its landmarks while preserving each model’s proportions. The desert-shell API below remains available for individual tile studies; the continuous host is implemented in the map preview.

const tile = createDesertTile({
  compact: true,
  biome: 'coast', // desert | coast | valley | city
  surface, waveTextures, time,
  sharedEdges: [3, 4] // skip internal skirts; edges 0–5 from east, clockwise
});
const centre = tileCentre(q, r, 9);
tile.root.position.set(centre.x, 0, centre.z);

The viewer uses one renderer, camera and clock, with projected labels, host water, foliage wind and gentle changes in neon brightness. Select a world to centre its whole tile. Zoom is bounded from the four occupied tiles to one complete tile; smaller views switch to the overview GLBs. Both LODs are preloaded for this four-tile example. Large-world streaming is not implemented in this prototype.

These are reduced original 3D meshes. Source shading is simplified for map scale: Tidewater’s wood, paint and hull colour nodes are baked at low frequency; Punk’s darkest wall colours are lifted for daylight readability. Sakura retains its native blossom cutout texture. The source worlds’ full lighting and post-processing are not loaded. The continuous map adds live planar reflection and refraction, using a lightweight adaptation of Tidewater’s waves and water optics. Its compute FFT, wake and surf simulations are omitted at map scale.

Supply two self-contained GLBs with the same anchor. Opaque surfaces and alpha-cutout foliage (alphaMode: MASK) are supported; blended transparency is rejected. At most two textures and 2 MiB of decoded texture memory are allowed. The loader measures the real download and geometry, and mounting checks the transformed bounds again. External asset references, animation clips, skins, morph targets, lights and cameras are rejected. This keeps lighting and bounded animation in the host. An optional mesh extras.role = 'foliage' enables subtle host-controlled wind.

The view chooses detail by projected tile size, uses one clock and renderer, stops animation in hidden tabs and starts paused with reduced motion. Zoom runs from the displayed composition to one complete tile. Keep shared host rendering costs separate from each creator's budget. These per-tile limits are a starting point; a large map still needs visible-tile loading and an overall scene budget.

corepack pnpm map:build:lagoon-lite

This rebuilds the component from the preserved native Lagoon source using installed Chrome. The manifest records the source revision, simplifications, source triangle count, sizes and hashes. The native connected group has 2,444,193 triangles; the map uses 23,384 at tile detail and 7,920 in the overview, reductions of 99.0% and 99.7%. Both use two draw calls and one embedded leaf atlas (512 px / 256 px). Enclosed furniture and roof lining are omitted in the overview. Original material base colours are sampled into vertex colours; foliage retains its native texture. Scene-specific shaders and normal maps are omitted. Duplicate, degenerate and flat ground faces are removed after position quantization to prevent z-fighting. Both LODs pass the shared budgets before the build replaces any public assets.

This is a separate prototype. The current map, walking world and CLI below retain their existing formats. Playable collision integration, map-landmark CLI scaffolding and registry publishing are not switched over by this study. The package is available in the workspace; it is not published to npm yet.

01 / START A TILE

Give your world a place.

Run these commands from the Threetopia workspace after corepack pnpm install. The starter includes a world manifest, mandatory map.json and a real example GLB terrain. Replace it with your playable scene; world.scene and map.source must refer to the same asset.

pnpm threetopia slots --registry public/atlas/registry.json
pnpm threetopia create my-world --tile 1,-1 \
  --registry public/atlas/registry.json --connect SW
pnpm threetopia check my-world
pnpm threetopia preview my-world

Choose a free tile in the first incomplete ring. This creates a proposal; it does not reserve or publish a tile. The creator preview renders your actual GLB with WebGPU. The public map uses lightweight captures of the integrated world with WebGL.

02 / COMPOSE YOUR TILE

Render the world you can visit.

The active map consists of transparent images captured from loadSharedScene, the same factory used by the walking world. It uses the same two-metre terrain mesh, source geometry, materials, object transforms and paths. There are no generated island illustrations in the active map.

// Start Vite in one terminal, then capture with installed Chrome:
MAP_CAPTURE_URL=http://127.0.0.1:55010 pnpm map:capture

// Development-only capture view; it is excluded from production builds:
/scripts/atlas/capture.html

The capture command writes one tile at a time to public/map/renders/ and its layer metadata to public/map/tiles/. Terrain and structures form the base. Source vegetation, waterfalls and billboards receive separate transparent passes when those objects exist. Other geometry still occludes the extracted objects. Nothing is added just to decorate the map.

Every pass uses an orthographic camera at −20° yaw and 45° elevation. Positions are measured in metres; tile-local X points right and map Y points down. The SDK’s projectMap(x, z, height) uses this same projection for markers, tile outlines and the player. The capture includes its source identity, camera and a SHA-256 revision. After changing the world, regenerate the captures before publishing.

// Source contract used by the default CLI starter:
{
  "version": 3, "kind": "scene-tile",
  "units": "metres", "origin": "tile-centre", "radius": 400,
  "source": {"kind": "gltf", "url": "assets/world.glb"},
  "bounds": {"minY": -12, "maxY": 180},
  "omit": [],
  "landmarks": [{
    "id": "arrival", "label": "Arrival",
    "position": [0, 2.4, 0], "kind": "spawn"
  }]
}

The public renderer consumes version 2 image-tile captures. Each layer supplies src, position, size and anchor. Each tile is a Three.js group, and all its planes use one scene, camera and clock. Portable image paths must be relative to map.json. The --format image option remains available for importing captured layers; it does not verify that an arbitrary image matches a world.

The capture command currently supports the four integrated runtime adapters. A new GLB can be validated and previewed immediately; integration into the shared capture scene is still a maintainer step. There is no automatic remote publishing service.

03 / MOTION & LANDMARKS

Animate the captured details.

Only animate objects that exist in the playable scene. The active map uses subtle foliage, water and billboard effects over real captured pixels. These are lightweight map effects, not a live simulation of the walking world. Built-in sprite animations are float, sail, drift, petals and sway. Use durations of 4–180 seconds, travel up to 300 art units on each axis and rotation up to 45°. Translation and rotation stay relative to the declared anchor; the map camera never changes those local coordinates.

Use isolated: true for a separately captured transparent component; this preserves its full alpha silhouette. Shader effects support waterfall, ripple, light, foliage and cloud. Waterfalls and surface effects can sample a crop of the landscape. Their crop rectangle is [x, y, width, height], measured from the source image’s top-left in fractions. Match its placement exactly:

size = [terrain.size[0] * crop[2], terrain.size[1] * crop[3]]
anchor = [0.5, 0.5]
position = [
  terrain.position[0] + (crop[0] + crop[2]/2 - terrain.anchor[0]) * terrain.size[0],
  terrain.position[1] + (crop[1] + crop[3]/2 - terrain.anchor[1]) * terrain.size[1]
]

These are scene objects, not screen overlays. A crop and its landscape therefore keep the same scale and position through camera movement. Give clouds an effect: {kind: "cloud", seed: 12, speed: 0.7, travel: [60, -12]} and omit src. Three.js renders their procedural volume. Use grounded: true for small waterfall spray; free clouds render above the islands.

Add up to 32 landmarks with stable IDs, labels and tile-local art positions. Accessible HTML labels are projected with the same Three.js camera used for the art. Layer controls can hide a whole tile or an individual component.

import {ImageAtlasRenderer} from '@threetopia/world-map/image-renderer';
import '@threetopia/world-map/image-renderer.css';

// Each registry tile supplies q, r, edges and an imageMap JSON URL.
const view = new ImageAtlasRenderer(element, registry, {
  onSelect: place => showPlace(place),
  onError: error => showError(error)
});
await view.ready;
view.fit();
view.setOptions({motion: false});
// view.getLayout() exposes actual scene anchors for alignment checks.
// When removed: view.dispose();

04 / SHARED EDGES

Keep both sides connected.

Each complete world occupies one hex tile, 693 metres between opposite sides and 800 metres between opposite corners. Lagoon is the centre; the world expands around it. Six Wang signatures are ordered E, SE, SW, W, NW, NE.

SignaturePhysical contract
open-seaSeabed −12 m, sea level 0 m. Coast stays inside the tile.
shore-pathMatching boundary profile, a centred 2.8 m walking port and 2.4 m ground at the crossing.

Join the actual terrain and path on both sides before capturing. The capture clips to the physical tile boundary and sea level. It does not paint over a gap. Tile outlines remain optional creator guides.

A new path requires agreement on both neighbouring tiles. The CLI reports a mismatch until both signatures agree. Image validation does not prove a physical crossing is walkable; that requires integration review.

05 / CAMERA & PERFORMANCE

One tile to the whole world.

Maximum zoom-in fits one complete tile, including its moving objects. Maximum zoom-out fits all occupied tiles with room for controls. Both limits adapt to screen size and new occupied tiles. Empty creator slots do not extend the zoom range. A one-tile preview therefore has one scale. Drag to pan; Home shows all worlds.

ResourceLimit
Map metadata64 KiB per tile
Each image2 MiB
Separate components / landmarks32 / 32 per tile
Layer sizeUp to 1600 × 1600 art units

Keep source image dimensions modest as well as compressed bytes: transparent textures still use GPU memory after decoding. Reuse textures across components. The renderer uses one map canvas, shares repeated textures, caps its pixel buffer near 2.1 million pixels and targets 30 animated frames per second. Camera interactions redraw immediately. All animations share a clock, pause together and stop in hidden tabs. Reduced motion starts paused.

The minimap is static until its contents or player position change. Opening the large map moves this same map canvas and texture set into the dialog; closing returns it to the minimap. The playable world keeps its own renderer. The standalone map downloads only the scene captures, not the full source worlds.

The current renderer loads the registered tiles into memory. Larger registries will need visibility-based loading and texture eviction; this is not yet an unlimited-world streaming renderer.

06 / CLI REFERENCE

Validate and preview independently.

CommandBehaviour
create <dir> --tile q,rCreates a world manifest, mandatory scene map, a real GLB terrain and README. Preserves existing directories.
slots --registry fileLists ocean slots in the first incomplete ring.
check [dir]Checks that playable scene and map source agree, GLB geometry bounds and budgets. Image mode checks its layers, local files and bounded motion. Add --registry for placement and neighbour checks.
preview [dir]Serves the real GLB preview, or the composition renderer for captured images. Optional --port 5195.
build [dir]Emits self-contained dist-map/ with its assets, renderer, local Three.js and metadata.

The packages are available in this workspace. There is no npm release or remote publishing service yet.

Scene requirements

The default starter uses version 3. world.scene and map.source must match. Use an embedded, uncompressed GLB, XYZ landmarks and valid height bounds; budgets are 64 MiB and 2 million triangles. Custom shaders and instancing need a runtime adapter. Keep decorative map-only buildings or terrain out of the capture pipeline.

07 / PLACEMENT PROPOSALS

Grow around the centre.

  1. Open the map and choose Build here.
  2. Select an ocean tile and review its neighbours.
  3. Copy the starter command or download a placement proposal.
  4. Create your playable world, verify its scene preview and integrate its map captures.
  5. Coordinate crossings and validate both neighbours.
  6. Submit the package and proposal for integration.

Selections are shareable by URL. They remain proposals until integrated.
